# PS-0006: 다른 작업의 미커밋 변경이 커밋에 섞임

- 날짜: 2026-10-05
- 영역: 작업 절차
- 영향: main 문서 오기(존재하지 않는 디자인 토큰 작업을 "부분 완료"로 표시) — P2
- 수정: `8041941`
- 관련: CLAUDE.md "작업 방식"

## 증상

ingress 문서 반영 커밋 `a84d95c`에 다른 작업의 미커밋 변경이 들어갔다. 작업계획서에 디자인 토큰이 "부분 완료"로 표시되었지만 main에는 `packages/design-tokens`가 없었다.

## 원인

같은 checkout에서 여러 작업(다른 세션의 디자인 토큰 작업)이 진행 중이었다. PR을 다시 쌓으면서 수정 전 커밋을 cherry-pick했고, 공유 파일(`docs/plan/work-plan.md`)의 다른 작업 변경이 함께 stage되었다.

## 해결

해당 줄을 원래 문구로 되돌렸다.

## 재발 방지

- 파일 단위 stage(`git add <path>`)만 쓰고 `git add -A`·`git add .`는 쓰지 않는다. 커밋 전에 `git diff --cached`를 확인한다.
- 다른 작업이 진행 중인 checkout에서는 `git worktree`로 분리된 작업 디렉터리를 쓴다.

## 교훈

공유 문서(작업계획서, registry)는 여러 작업이 동시에 고치는 충돌 지점이다. hunk 단위로 확인한다.

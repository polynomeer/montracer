# PS-0008: debounce로 URL에 반영한 뒤 입력 중이던 글자가 되돌려짐

- 날짜: 2026-10-08 (발견) / 2026-10-08 (해결)
- 영역: web (apps/web) — S04 Trace Explorer, S08 Logs·Metrics 조건 입력
- 영향: 사용성 — 느린 기기·바쁜 탭에서 친 글자가 사라진다. 시험이 가끔 실패한다(flaky). 데이터·tenant 영향 없음. 심각도 P2
- 수정: PR polynomeer/montracer#45, `apps/web/src/app/useDraft.ts`
- 관련: ADR 0043·0045·0047(입력은 300ms 뒤 또는 Enter에 반영, D05 §03), ADR 0041(URL이 조사 상태의 원천)

## 증상

Overview PR의 전체 web 시험을 반복해 돌리던 중, S08 Logs의 "조건 입력" 시험이 약 열 번에 한 번 실패했다. 이 시험은 본문 검색어를 입력하고 조회를 누른다. 단독으로 돌리면 늘 통과했다.

## 원인

조건 입력은 세 단계로 동작했다.

1. 입력 값은 컴포넌트 상태(초안)에 둔다.
2. 300ms debounce 뒤 URL에 쓴다(`setSearchParams`).
3. URL 값이 바뀌면 `useEffect`가 초안을 URL 값으로 다시 맞춘다(뒤로 가기·링크 복원용).

글자 사이가 300ms를 넘으면(느린 기기, 바쁜 이벤트 루프) 다음 순서가 생긴다.

1. debounce가 중간 값(`tim`)을 URL에 쓴다.
2. router 상태가 갱신되기 전에 사용자가 더 친다(`timeo`).
3. URL이 `tim`으로 바뀌어 3번 동기화가 초안을 `tim`으로 되돌린다. 그 사이 친 글자가 사라진다.

3번 동기화는 "바깥에서 바뀐 URL"과 "우리가 방금 쓴 URL"을 구분하지 않았다. 같은 패턴이 S04(span 이름·최소 duration), S08 Logs(본문·trace ID), S08 Metrics(조건 행)에 있었다. Metrics에서는 편집 중인 빈 조건 행도 지워질 수 있었다.

## 해결

`useDraft` hook에 동기화를 모았다.

- debounce·조회가 URL에 쓸 때 **정규화한 값**(trim·소문자·빈 행 제거)을 hook에 알린다(`committed`).
- URL이 그 값으로 바뀌면 초안을 건드리지 않는다. 그 밖의 URL 변경(뒤로 가기·링크·다른 조건)만 초안에 다시 넣는다.

버린 대안은 둘이다.

- **입력 중(focus) 동기화 끄기:** focus를 유지한 채 뒤로 가기를 하면 복원되지 않는다.
- **debounce 없애고 Enter만:** D05 §03(300ms 반영)과 다르다.

## 재발 방지

- 시험: `apps/web/src/app/useDraft.test.ts`
  - 반영한 값으로 돌아오는 URL 변경은 초안을 유지한다(그 뒤 친 글자 포함).
  - 바깥 변경(이전 값으로의 뒤로 가기 포함)은 초안을 바꾼다.
  - 배열 값에서 편집 중인 빈 행이 남는다.
- 타이밍을 흉내 낸 화면 시험(글자 사이 350ms)은 경합 구간이 짧아 고치기 전 코드도 통과했다. 그래서 규칙을 hook 단위로 고정했다.

## 교훈

URL을 원천으로 두고 입력을 debounce로 반영할 때, "URL → 입력" 동기화는 자기가 쓴 값과 바깥 변경을 구분해야 한다. 가끔 실패하는 화면 시험은 재시도로 넘기지 말고 경합을 찾는다.

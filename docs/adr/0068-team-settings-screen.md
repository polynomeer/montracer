# ADR 0068: 설정 > Team 화면과 초대 수락 페이지 (F07 단계 C — 화면)

- 상태: 승인 (결정 위임 — polynomeer, 2026-10-05 "빅테크 사례 기준으로 결정하고 근거를 기록". 2026-10-20 다음 작업 선택 "멤버 관리 API·화면")
- Owner: Frontend lead
- 날짜: 2026-10-20 (제안·결정)
- 관련: F07, E01 · D05 §01(Admin 탐색 영역), §03(상태 계약), §04(권한 표시는 보안 경계가 아님) · D04 §01, §12 · ADR 0065(화면 로그인), 0066(step-up), 0067(멤버·초대 API)

## 배경

ADR 0067로 멤버·초대 API가 생겼다. 하지만 고객 관리자가 쓸 화면이 없다. 초대 링크(`/invite#token`)를 여는 페이지도 없다.

D05는 Admin 탐색 영역에 Team을 두고 화면 ID를 정하지 않았다(`settings/team`, D05 §01). 다음 다섯 가지는 정하지 않았다.

- step-up을 화면에서 어떻게 안내하는가
- 역할 변경·제거의 확인 방식
- 초대 링크 1회 표시
- 초대 수락 확인
- Admin 메뉴를 누구에게 보이는가

## 결정

### 1. 위치와 메뉴

- 화면은 `/o/{org}/settings/team`이다. Admin 그룹의 Team 항목이다.
- Admin 메뉴는 session 역할이 Tenant Admin·Security Auditor일 때만 보인다. 멤버를 볼 수 있는 역할이다.
  - 표시 정책일 뿐 보안 경계가 아니다. 서버가 요청마다 다시 인가한다(D05 §04).
  - 로그인 꺼짐(API key 모드)에서는 역할을 모르므로 메뉴를 숨긴다. 주소로는 들어갈 수 있다.

### 2. step-up 안내 — 미리 알리고, 거절되면 바로 재인증

- Tenant Admin이 보면 session의 `step_up_expires_at`에 따라 둘 중 하나를 보인다.
  - 유효하면 "추가 인증이 HH:MM까지 유효합니다"를 보인다.
  - 아니면 "멤버를 바꾸려면 추가 인증이 필요합니다" 안내와 **추가 인증(MFA)** 버튼을 보인다.
- 변경 요청이 403 `details.step_up_required`로 거절되면 경고로 바꾸고 같은 버튼을 보인다.
- 버튼을 누르면 다음 순서로 진행된다.
  1. `POST /api/v1/auth/step-up {return_to: 지금 화면}`을 보낸다(CSRF).
  2. IdP 재인증으로 이동한다.
  3. 성공하면 지금 화면으로 돌아온다(전체 다시 불러오기 — 새 step-up 시각을 session에서 다시 읽는다).
- 재인증이 실패하면 로그인 화면에 이유가 보인다. 로그인은 살아 있으므로 "하던 화면으로 돌아가기" 링크가 있다. 같은 사이트 경로만이다.

### 3. 멤버 표

- 열은 이름(IdP 이름, 없으면 user id), "(나)" 표시, 역할, 마지막 로그인이다.
  - 로그인 기록이 없으면 "로그인 기록 없음"으로 적는다. 빈칸이나 0으로 두지 않는다(계약 6).
- **역할 변경**은 행의 선택 상자로 바로 보낸다(If-Match = 목록의 `revision`).
  - 자기 역할을 바꿀 때만 확인을 받는다. 바로 관리 권한을 잃을 수 있다.
  - 실패 처리
    - 412: "다른 관리자가 먼저 바꿨습니다" 후 목록을 다시 읽는다.
    - 409: 서버 문장을 그대로 보인다(마지막 관리자).
    - 404: 다시 읽는다.
- **제거**는 행 안의 확인(빼기… → 빼기/취소) 뒤에 보낸다.
  - 자기 자신이면 "다시 들어올 수 없습니다"를 알린다.
- Security Auditor는 보기만 한다. 변경 버튼과 초대 영역이 없다.

### 4. 초대 링크 1회 표시

- 역할 선택(tenant_admin 없음)과 선택 메모(64자)로 만든다. Idempotency-Key는 누를 때마다 새로 만든다.
- 링크는 응답에서 한 번만 보인다.
  - 컴포넌트 상태에만 둔다(저장·로그 없음). 닫으면 사라진다.
  - 알림 policy secret 표시(ADR 0056)와 같은 방식이다: 제목에 focus를 주고 role=alert는 쓰지 않는다(값을 소리 내어 읽지 않게). 복사 버튼과 실패 안내가 있다.
- 대기 중 초대 표(역할·메모·만든 사람·만료)에서 폐기한다.
- 목록을 불러오지 못하면 "초대가 없다는 뜻이 아닙니다"라고 구분한다(D05 §03).

### 5. 초대 수락 페이지 `/invite`

- 조직 화면 밖이다(아직 member가 아니다). 다음 순서로 진행된다.
  1. fragment의 token을 읽고 **바로 주소에서 지운다**(`history.replaceState`). 뒤로 가기·화면 공유·북마크에 남지 않는다.
  2. token을 본문으로 보내(`POST /api/v1/auth/invitation`) 들어갈 **조직 이름과 역할**을 받는다.
  3. "acme 조직에 Developer로 들어갑니다"를 보이고, "모르는 조직이면 들어가지 마세요"를 함께 보인다.
  4. 사용자가 **참여하고 로그인**을 눌러야 IdP로 이동한다. 남이 보낸 링크로 모르는 사이 다른 조직에 들어가지 않게 한다(ADR 0067 §5).
- 실패 처리
  - 쓸 수 없는 초대(404)·token 없음: 새 링크를 요청하라고 안내한다.
  - Origin 거절(403): 링크를 직접 열라고 안내한다.
- callback 실패(`invitation_invalid`)는 로그인 화면에 같은 안내가 보인다.

## 후보

| 후보 | 이점 | 비용·위험 |
|---|---|---|
| A (채택) 미리 알리는 step-up 안내 + 거절 시 바로 재인증, 행 단위 역할 선택(자기 자신만 확인), 행 안 확인 뒤 제거 | 재인증이 언제 필요한지 먼저 안다. 남의 역할 바꾸기는 한 번에 끝난다 | 남의 역할을 잘못 고르면 바로 반영된다(되돌리기 쉬움, 감사에 남음) |
| B 변경을 누를 때마다 확인 대화상자 | 실수가 줄어든다 | 대량 정리 때 마찰이 크다. 역할 변경은 되돌릴 수 있다 |
| C step-up을 화면 진입 때 강제 | 단순하다 | Security Auditor·조회만 하는 관리자에게 불필요한 MFA. 15분 뒤 다시 막힌다 |
| D 초대 수락을 바로 IdP로 보냄(확인 없이) | 한 단계 줄어든다 | 남이 보낸 링크로 모르는 조직에 들어가 일할 수 있다(리뷰 지적, ADR 0067 §5) |

## 결과

- 이점: 고객 관리자가 화면에서 멤버를 들이고 관리한다. 초대 수락 전에 사용자가 조직을 확인한다.
- 비용 / 운영 부담: 없음(화면만).
- 영향 받는 계약
  - web route `/o/{org}/settings/team`, `/invite`
  - dev proxy가 `/api/v1/members…`·`/api/v1/invitations…`를 control-api로 보낸다
  - API client에 PATCH를 추가했다
  - consumer contract가 fixture를 OpenAPI로 검사한다

## 기능 상태

- F07: 멤버 관리(API·화면)를 마쳤다.
- 조직 정지 때 API key 막기와 key 관리 화면(Access)은 남았다.

## Rollback

- 이전 web 빌드로 되돌린다. API는 그대로 남는다(ADR 0067 flag로 따로 끈다).

## 재검토 조건

- 멤버가 1,000명을 넘는 조직이 생기면 검색·쪽 넘기기를 정한다(지금은 처음 1,000명과 안내).
- SCIM(F08)이 들어오면 IdP가 관리하는 멤버를 화면에서 읽기 전용으로 표시할지 정한다.

## 근거 (빅테크 사례)

- **GitHub organization People**
  - 멤버 목록에서 역할을 바꾸고 제거한다. 대기 중 초대를 별도 목록에서 취소한다.
  - 민감 작업 전에는 sudo mode 재인증을 요구한다.
  - 근거: GitHub Docs "Managing membership in your organization", "Sudo mode".
- **Google Workspace Admin console**
  - 관리자 작업 전에 "Verify it's you" 재인증을 요구한다. 재인증 뒤 원래 작업으로 돌아온다.
- **Slack 초대 수락**
  - 링크를 열면 들어갈 workspace 이름을 먼저 보이고, 사용자가 참여를 누른다.
- **GitHub·Grafana의 1회 표시 token UI**
  - 만든 직후 한 번만 보이고 복사 버튼과 "다시 볼 수 없음" 안내를 둔다(ADR 0056과 같은 근거).

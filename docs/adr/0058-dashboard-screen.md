# ADR 0058: S10 Dashboard 화면 — 보기·편집·변수·조회 묶음 (S10 단계 B)

- 상태: 승인 (결정 위임 — polynomeer, 2026-10-05 "빅테크 사례 기준으로 결정하고 근거를 기록". 2026-10-14 다음 단계 선택 "S10 Dashboard 화면")
- Owner: Frontend lead
- 날짜: 2026-10-14 (제안·결정)
- 관련: F05, E05 · D05 §03·§04·§10~12, D02 §14 · 계약 5·6 · ADR 0041, 0047, 0054, 0057

## 배경

ADR 0057이 dashboard 정의·저장·API를 만들었다. 화면에 대해 D05가 정한 것은 다음과 같다.
- **D05 §10**
  - 보기와 편집을 나누고, 위젯 추가 → query → display → preview → 배치 → publish 순서다.
  - autosave는 로컬 또는 서버 draft에만 하고, 마지막 published revision이 공유 화면이다.
  - 동시 revision 충돌은 차이를 보여주고 duplicate 또는 재적용을 고른다.
  - drag 대신 키보드 이동과 resize dialog를 쓴다.
  - 위젯 filter는 전역 변수와 override를 badge로 구분한다.
  - 같은 query는 합치고, view당 병렬 6개, 최대 50 위젯이다. 보이지 않는 탭은 fetch를 멈춘다.
- **D05 §11:** 자동 갱신 30초(비활성 탭 pause), 변수의 무권한 값은 옵션에서도 제거, 링크 접근 때 권한 재검증, "50 query를 한 번에 발사하지 않는다".

명세가 정하지 않은 것이 있다.
- 변수 값을 어디에 두는가
- 변수 선택지를 어디서 얻는가
- 위젯별 값 표시(요약 값, 상위 목록에서 값이 없는 행)
- 로컬 초안의 저장 위치와 수명
- 충돌 때 "재적용"의 의미
- 좁은 화면 배치

## 결정

### 1. 경로·메뉴

- `/o/{org}/dashboards`(목록)
- `/dashboards/new`(만들기)
- `/dashboards/{id}`(보기)
- `/dashboards/{id}/edit`(편집)

메뉴는 Organize > Dashboards(기존 정보 구조, D05 §01)다. 로컬 dev proxy는 `/api/v1/dashboards`를 control-api로 보낸다.

### 2. 보기

- **변수**
  - 값은 URL `var-이름`에 남는다(빈 값 = 전체). 그래서 공유 링크가 같은 거르기를 연다. 없으면 정의의 기본값이다.
  - URL 값은 외부 입력이다. 1~256 byte이고 제어 문자가 없어야 한다(서버와 같은 규칙). 아니면 버리고 기본값을 쓰며 그렇다고 알린다.
  - 선택지는 이 사용자가 볼 수 있는 서비스 목록(`GET /services`, 조회 권한 범위)의 서비스 이름과 환경이다. 권한 밖 값은 나오지 않는다(D05 §11).
    - 지금 값(기본값·URL)이 목록에 없으면 고를 수 없는 "(목록에 없음)"으로 따로 보인다. 선택지에 섞지 않는다(리뷰 반영).
  - 서비스가 200개를 넘으면 그렇다고 적는다.
- **위젯 조회:** 정의의 `$이름`을 고른 값으로 바꾼다. 변수가 "전체"면 그 조건을 빼고, 빈 문자열로 거르지 않는다.
  - **상단 환경(조사 context, D05 §11 "공통 context"):** 위젯이 환경을 직접 거르지 않으면 `deployment.environment.name = 상단 환경`을 더한다(리뷰 반영).
    - 위젯의 환경 조건(고정 값 또는 고른 환경 변수)이 앞선다. 환경 변수가 "전체"면 상단 환경을 따른다.
    - 화면에 "상단 환경(prod)으로 거릅니다"를 적는다.
  - 시계열은 범위에 맞는 step이다(서비스 상세와 같은 `metricWindow`).
  - 요약 위젯(stat·table·top_list)은 범위 전체 한 점이다. 분위수를 평균하지 않는다(계약 5, ADR 0042).
  - `time_override`는 지금부터 그만큼이다.
  - 7일을 넘으면 그리지 않고 이유를 적는다.
- **조회 묶음(`QueryPool`)**
  - 진행 중인 같은 조회(정규화한 query JSON)는 한 요청을 같이 기다린다.
  - 동시 6개이고, 나머지는 차례로 기다린다.
  - 기다리는 위젯이 모두 떠나면 요청(또는 대기)을 취소한다.
  - 결과는 위젯 상태로만 간다. 전역 store에 두지 않는다(D05 §04).
- **갱신:** 30초마다 한다. 숨은 탭에서는 멈추고, 다시 보이면 놓친 갱신을 한 번 한다. 마지막 갱신 시각을 보인다.
  - 위젯 화면 상태의 key는 조회 조건(위젯·고른 값·상대 범위 이름·시간 덮어쓰기)이다. 분마다 움직이는 절대 시각은 넣지 않는다(리뷰 P1).
    - 그래서 갱신 중에도 이전 값이 남는다. 실패하면 마지막 값과 "갱신 실패(시각)" 배지, 다시 시도 버튼을 보인다.
    - 실제 조회(같은 query 합치기 key)는 그때의 절대 범위로 만든다.
  - 새로고침 버튼은 정의도 다시 읽는다(다른 사람이 publish한 정의). 머리에 revision과 마지막 수정 시각·사람을 보인다(D05 §03).
- **값 표시(계약 6)**
  - 값이 없으면 이유를 보인다(데이터 없음·집계 중·받은 metric 없음).
  - 일부만 집계된 값은 "일부"다.
  - 저장소 일부가 응답하지 않은 결과(`meta.partial`)는 "일부 저장소 응답 없음" 배지를 달고, 값에 "(일부)"를 붙인다(리뷰 P1, D05 §03 우선순위 실패 > partial).
  - 위젯마다 live region을 두지 않는다. 50개가 갱신마다 읽히지 않게 한다(D05 §12). 오류는 정적 글이고 request_id와 다시 시도 버튼이 있다.
  - 조회 실패는 실패로 보인다. 마지막 성공 뒤 실패하면 그 값을 유지하고 "갱신 실패(시각)" 배지를 붙인다.
  - 상위 목록·표에서 값이 없는 행은 0으로 정렬하지 않고, 값 있는 행 뒤에 이유와 함께 둔다. 한도에서 잘리면 나머지 수를 적는다.
- **배지:** 변수를 쓰는 위젯은 `$이름` 배지를, 시간 덮어쓰기는 "최근 1d" 배지를 단다(D05 §10).
- **text 위젯:** 글자 그대로 보인다. HTML·markdown을 해석하지 않는다(CLAUDE.md text-only).
- **배치:** 24열 CSS grid이고 행 높이는 40px다. 768px 미만은 읽는 순서(위→아래, 왼→오른쪽)로 한 줄씩 쌓는다. grid 위치는 CSS 변수로 넘겨 좁은 화면 규칙이 덮을 수 있다.

### 3. 편집

- **편집 대상:** 정보(제목·설명), 변수(이름·종류·기본값), 위젯 목록
  - 위젯마다 편집(종류·제목·단위·metric·연산·group·조건·표시·시간), 위치·크기, 삭제가 있다.
  - 위젯 편집의 "미리보기"는 지금 입력으로 위젯 값을 그린다(D05 §10 query → display → preview, 변수는 기본값).
  - 배치 미리보기는 24열 grid다.
  - 위젯 편집·위치 대화는 열리면 첫 입력으로 focus가 가고, 닫으면(적용·취소·Esc) 연 버튼으로 돌아온다.
  - 방금 추가한 위젯의 편집을 취소하면 그 위젯을 지운다(빈 위젯이 남지 않게).
  - 시계열 "쌓아 보기"는 화면에 두지 않는다. 그리는 쪽이 없고, 분위수·평균을 쌓으면 분위수를 더하는 것과 같아진다(계약 5). 정의 필드는 false다.
- **키보드 배치:** 위치·크기 대화에 숫자 입력과 한 칸씩 옮기기 버튼이 있다. 열리면 첫 입력으로 focus가 가고, Esc로 닫는다. 겹침과 24열 초과는 적용하지 않는다(서버와 같은 규칙, D05 §10).
- **화면 검사(서버가 최종 검증)**
  - metric 필수, group ≤ 5
  - stat은 group 없음, top_list는 group 하나 이상
  - 조건 값의 `$이름`은 있는 변수이고 그 종류의 field여야 한다.
  - 변수 이름 형식과 중복
  - histogram 위젯·team 변수는 고를 수 없다(ADR 0057, 422). 왜 없는지 적는다.
- **저장 전 전체 검사:** 서버 422로만 알게 되지 않게 저장 전에 정의 전체를 본다(리뷰 반영).
  - 제목, 변수 이름·기본값
  - 위젯(빈 metric·글, stat·top_list group 규칙, 끊긴 `$이름` 참조 — 변수를 지우거나 이름을 바꾼 경우)
  - 배치(겹침·24열)
  - 위젯 추가는 grid 행 한도 안에서만 된다.
- **로컬 초안:** 편집 중인 정의는 이 브라우저 `localStorage`에 1초 뒤 저장된다(dashboard·조직별 key, 기준 revision과 기준 정의 포함).
  - 편집을 원래대로 되돌리면 초안을 지운다.
  - 다시 열면 복원·버리기를 묻는다. 기준 revision이 지금과 다르면 그 사실도 알린다.
  - 저장소를 쓸 수 없으면(사생활 보호 창 등) 초안 없이 동작한다.
  - 저장하거나 버리면 지운다.
  - 서버 원본이 아니라 사용자의 편집본이다.
- **저장 = publish:** 만들기는 Idempotency-Key(편집 화면 하나에 하나), 수정은 If-Match다.
- **충돌(412):** 덮어쓰지 않는다. 최신본을 읽어 "그 사이 바뀐 것(기준 → 최신)"과 "내 편집(기준 → 내 것)"을 줄로 보이고(D05 §10), 다음 중 고른다.
  - 기준은 편집을 시작한 서버 정의다. 이전 revision 기준 초안을 복원했으면 그 초안의 기준 정의다(리뷰 P1 — 그렇지 않으면 남의 변경이 "내 편집"으로 보여 재적용 때 조용히 사라진다).
  - **내 편집을 최신 위에 다시 적용:** 내 정의 전체를 최신 revision으로 저장한다. 그 사이 바뀐 것은 내 정의로 대체된다. 바뀐 것을 먼저 보였다.
  - **새 dashboard로 복제해 저장:** "(복사본)" 제목. Idempotency-Key는 충돌 하나에 하나다(다시 눌러도 복제본이 둘 생기지 않는다).
  - **내 편집 버리고 최신 보기:** 초안도 지운다.
- **삭제:** 확인 대화(focus 이동·Esc, 진행 중에는 버튼을 막아 두 번 보내지 않음)와 If-Match(서버에서 읽은 revision)로 한다. 412면 최신 내용을 확인하라고 안내한다. 화면 안에 펼쳐지는 비모달 확인이라 focus를 가두지 않는다(ADR 0054·0056과 같다).

## 결과

- **web:** Dashboards 목록·보기·만들기·편집이 생긴다(`apps/web/src/features/dashboards`). API는 `src/api/dashboards.ts`다.
- **local dev:** proxy가 dashboard 경로를 control-api로 보낸다.
- **API·schema 변경 없음.** tenant 영향은 없다(조회는 보는 사람의 권한으로 query-api가 다시 인가한다).
- **requirements-registry:** F05는 `planned`로 둔다. 출시 성숙도 상태이고 Gate 증거 전이다(ADR 0057과 같은 기준).
- 번들이 약 41kB(gzip 11kB) 커진다. 화면별 code splitting은 재검토 조건이다.

## Rollback

- web 배포를 되돌리면 placeholder로 돌아간다. 정의는 API에 남는다.
- control-api flag(`MONTRACER_DASHBOARD_API_ENABLED=false`)면 화면은 "이 배포에서는 쓸 수 없습니다"(목록)·"찾을 수 없습니다"(보기·편집)를 보인다.

## 재검토 조건

- 서버 draft·revision 고정 공유(ADR 0057 명세 차이)
- 위젯 단위 병합(충돌 재적용)
- CSV export(별도 권한·10k행·formula injection, D05 §11)
- 위젯 metric 입력에 metric 사전(ADR 0046) 자동 완성
- 화면별 code splitting(번들 500kB 경고는 이 PR 전부터 있었다)
- 사용자 20명 × 12위젯 × 30초 갱신 부하(D06 §03 Dashboard 시나리오)
